# 批量链上记账（Merkle Anchor）v1（2026-10-29）

- 令：本地优先＋Web3 社区门户；自签早期；设备 DID／配对；**不发币**；每约 100 单打包上链记账。
- 判：**不做每单上链；做「链下账本＋每 100 单一个 Merkle 根锚定」；链上只放根/批次元数据/CID。**

## 一 模型

```text
本地 PA 账本（逐单）
  → 规范化记录 hash
  → 每 100 单（或超时）建 Merkle 树
  → 一个 batch：root / count / 时间窗 / CID / prevRoot
  → L2 一笔 anchor 交易
  → 社区门户可验 inclusion proof
```

- 不是 rollup，不做状态转换证明；是**批量存在性/顺序锚定**。
- 链上 **不存** 原始交易、用户身份、金额明细；只存承诺（commitment）。

## 二 记录与批次

- 单条记录规范化 JSON：`{id, ts, device_did, kind, amount?, counterparty_hash?, nonce, prev_hash}`；
- 金额/对手方等敏感字段可只放 hash；
- 单条 `leaf = keccak256(canonical_json)`；
- Merkle：排序对、域分离；`root` 每批一个；
- 批次：`batch_id, from_ts, to_ts, count, root, prev_root, cid`；
- 整批 JSON 存 IPFS/Arweave；CID 上链；
- **100 单/批** 可配；低流量按时间窗（如 24h）触发。

## 三 合约（最小、不可升级）

```solidity
struct Batch { bytes32 root; bytes32 prevRoot; uint64 count; uint64 fromTs; uint64 toTs; string cid; address anchorer; }
function anchor(bytes32 root, bytes32 prevRoot, uint64 count, uint64 fromTs, uint64 toTs, string calldata cid) external onlyAnchorer returns (uint256 batchId);
event Anchored(uint256 indexed batchId, bytes32 root, bytes32 prevRoot, uint64 count, string cid, address anchorer);
```

- `onlyAnchorer`：2-of-3 Safe 多签，防单点；
- 合约不可升级；变更用新合约＋新批次序号；
- 链选 L2（Base／Arbitrum／Optimism 之一），gas 约分级；
- 免费用户 gas 由运营方/paymaster 承担。

## 四 身份与信任

- 设备 DID：每台本地 PA 自生成密钥，不上传私钥；
- 钱包登录：SIWE，只做账户/社区身份；
- 配对：钱包 ↔ 设备 DID 一次性码/QR；
- 批次签名：anchorer 多签；
- **代码签名（自签/未来 OV）与节点/账本信任分离**；
- 门户连接靠设备密钥，不靠 exe 证书。

## 五 隐私与合规

- 链上只 hash/CID；个人数据、金额明细不上链；
- 公开批次可验证；私密批次用加盐 hash／选择性披露；
- 删除权：链下可删，链上 hash 不可删 ⇒ 不把个人数据写链；
- 中国境内：不发币、不做交易撮合、不承诺收益；
- 海外：按地区做 KYC/AML 评估（如涉及支付）。

## 六 社区门户职责

- 展示批次、root、CID、时间窗；
- 提供 inclusion proof 验证；
- 设备/钱包资料、社区动态、活动；
- 不托管用户账本明文；
- 发现 anchor 异常（root 不连续/缺批）时告警。

## 七 免费与成本

- 自签：0；
- 门户 HTTPS：Let's Encrypt 0；
- L2 anchor：每批约分级美分；100 单/批 ⇒ 单均极低；
- 运营方付 gas，或社区金库；不引入代币。

## 八 MVP

1. 冻结记录 schema 与 canonical JSON；
2. 写 `BatchAnchor` 合约＋单测；
3. 本地 PA 批量器（100 单/24h）；
4. 门户 verifier（CID→root→proof）；
5. 选一条 L2 测试网；
6. 暂不做代币、不做跨链、不做每单上链。
