## 三、本地软件自动化可行性评估(第二步)

### 技术点 1: 本地窗口截图
- WSL2 DISPLAY=:0 + PIL ImageGrab / gnome-screenshot 可用(WSL 内 Linux GUI)
- **关键限制**: 若 Autograph 是 Windows 原生程序, 在 Windows 桌面运行 → WSL 无法直接截/控
  → 需 Windows 侧截图/自动化(如 Windows 上跑 Python + pyautogui, 或 WSLg 集成)
- 结论: 截图可行(取决于软件运行环境), 需先确认软件跑在 Windows 还是 WSL

### 技术点 2: VLM 界面理解(Qwen2.5-VL)
- qwen2.5vl:7b 已在 11435 就绪, 之前测试确认能识别按钮/输入框/给坐标(优于 llava)
- 但 UI 复杂(运动图形软件工具栏密集) 7B 可能漏小图标; 建议截图分区放大提问
- 每问 ~90s(3.4 tok/s), 一个流程需 10-20 次 VLM 调用 → 30min 纯推理时间

### 技术点 3: 坐标执行(pyautogui)
- pyautogui 未装但可装; WSL 内可控制 Linux GUI; Windows 程序需 Windows 侧执行
- 坐标抖动 ±20-50px: 大按钮(>60px)安全; 小按钮(<30px)会点偏 → 需验证循环纠偏

### 技术点 4: 验证循环(操作后截图对比)
- 操作后截图 → VLM 对比目标态(「是否出现弹窗/按钮高亮/数值变化」)
- 半自动: 每步操作后用户确认(人机协同, 初期最可靠)
- 全自动: VLM 判断 success/fail + 重试(需阈值调优, 风险高)

### 技术点 5: SOP 落盘格式
- 建议: 结构化步骤 + 截图锚点 + 坐标 + 验证点
  ```
  ## 步骤 N: 打开项目
  操作: 点击左上 [新建项目](截图锚点 img1)
  坐标: (120, 80) ± 容差 40px
  验证: 出现项目属性面板([验证截图])
  ```
- 存 vault 平台规范/ 或 学习笔记/软件/Autograph/ 供 Agent 执行时 read

## 四、风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| Windows 原生程序不可被 WSL 控制 | 方案不可行 | 确认运行环境; 若 Windows 需 Windows 侧 agent_client 或远程截图 |
| 小按钮(<30px)坐标抖动点偏 | 操作失败 | 验证循环 + 点击后截图确认 + 重试 |
| VLM 7B 漏密集小图标 | 识别不准 | 分区放大截图; 关键区域多问几次 |
| VLM 90s/次, 流程 10-20 步 = 30min | 慢 | 半自动(用户确认关键步); 后续换更大模型 |
| 窗口大小/位置变化坐标失效 | 坐标不准 | SOP 记录相对位置(百分比)+窗口固定建议; 每次执行前截图校准 |
| 官网定位错误(可能非 Maxon) | 调研白做 | 第一步先向用户确认软件全名/来源 |

## 五、分阶段实施建议

1. **阶段0(确认)**: 用户确认 Autograph 全名/版本/运行环境(Windows or WSL)
2. **阶段1(官网调研)**: 抓官网+教程 → 学习笔记(现有能力, 立即可做)
3. **阶段2(截图+识别 PoC)**: 截一张 Autograph 窗口 → qwen2.5vl 识别按钮+坐标 → 验证 VLM 定位精度
4. **阶段3(单步执行 PoC)**: pyautogui 点一个按钮 → 截图验证 → 确认坐标抖动影响
5. **阶段4(流程录制)**: 用户演示 1 个完整流程(5-10 步) → Agent 逐步截图+识别+记录 → 生成 SOP
6. **阶段5(SOP 回放)**: Agent 按 SOP 执行 → 截图验证 → 人工兜底确认

## 六、结论

- **可行, 但强依赖运行环境确认**(Windows vs WSL 决定截图/控制方案)
- 建议先做阶段1(官网调研, 零风险) + 阶段2(截图识别 PoC, 验证 VLM 定位精度)
- 阶段2 的 PoC 结果决定后续(若 VLM 定位准→继续; 不准→需更大模型或人工标注)
