# 知乎文章发布 SOP（2026-08-23 实测）

> 环境：zhuanlan.zhihu.com 文章编辑器（Draft.js 富文本）
> 实测方式：browser_local（真实浏览器）+ playwright DOM 探针
> 未实测项已标注【待确认】，不编造

---

## 0. 基础选择器（config/platforms.yaml 已验证）

| 元素 | 选择器 | 备注 |
|---|---|---|
| 标题框 | `textarea[placeholder*="请输入标题"]` | 是 textarea 不是 input，最多 100 字 |
| 正文 | `[contenteditable=true].public-DraftEditor-content` | Draft.js，需键盘输入，fill 不适用 |
| 正文插图 | `input[type=file][accept*="image"]`（隐藏） | set_input_files 直传，插入光标处 |
| 预览 | `button:has-text("预览")` | Button--secondary |
| 发布 | `button:has-text("发布")` | Button--primary，页面底部右侧 |
| 草稿 | 自动保存，链接形态 `zhuanlan.zhihu.com/p/{id}/edit` | 无显式存草稿按钮 |

## 1. 封面选择 【部分实测】

- **入口**：发布设置面板 → `text=添加封面` / `text=添加文章封面`
- **格式要求**（页面文案）：`JPEG、JPG、PNG`
- **上传控件**（DOM 探针）：隐藏 `input[type=file].UploadPicture-input`，accept=`.jpeg, .jpg, .png`
- **交互**：点击后触发**原生文件选择框**（OS 级，extract 无法捕获，browser_local 无文件注入）
- **能否从正文图选**：【待确认】——点击后未见非原生弹层，需人工确认是否提供"从正文中选择"选项
- **操作步骤**：点「添加封面」→ 选本地图片（JPEG/JPG/PNG）→ 自动上传设为主图

## 2. 投稿至问题 【实测-须知弹窗】

- **入口**：发布设置 → `text=投稿至问题`（当前显示"未选择"）
- **首点弹窗**：「投稿须知」说明，内容：
  1. 含好物卡片、知+、教育等卡片的文章**不支持**投稿
  2. 超过发文限制的文章**不支持**
  3. 收录到付费专栏的文章**不支持**
  - 按钮：`text=我知道了`
- **搜索框**：【待确认】点「我知道了」后出现，选择器未捕获（推测 placeholder 含"搜索问题"）
- **操作**：点投稿至问题 → 我知道了 → 搜索问题 → 选择 → 保存

- **首点弹窗**：「创作声明」说明（用于虚构/剧透等场景，展示在开头）

- **入口**：发布设置 → `text=文章话题` / `text=添加话题`
- **首点弹窗**：「文章话题」说明（"绑定合适的话题，能方便分类检索…"）
  - 按钮：`text=我知道了`
- **搜索输入框**（DOM 探针，隐藏态）：`input[placeholder*="搜索话题"]`（class `Input i7cW1UcwT6ThdhTakqFm`）

## 5. 发布按钮 【实测-触发审批门，弹窗内容待确认】

- **位置**：发布设置栏**底部右侧**，`预览 | 发布` 相邻；左侧显示"字数：XXXX · 刚刚 · 草稿"
- **关键点**：点击 `text=发布` 会被系统**关键操作审批**拦截（防误发），需人工放行
- **确认弹窗内容**：【待确认】审批放行后可见（推测为"确认发布？"类弹窗，未实测）
- **操作**：人工确认发布 → 查看弹窗 → 确认（若弹窗含发布按钮，此步同样会触发审批）

## 通用交互规律（实测发现）

1. **所有发布设置项首次点击都弹"说明弹窗"**（投稿须知/创作声明/文章话题），含 `text=我知道了` 按钮——自动化流程需先过这一关
2. 设置项入口均为**面板内文本行**，用 `text=xxx` 选择器可命中
3. 发布是**不可逆关键操作**，必须走人工审批；草稿自动保存，随时可中断
4. 编辑器所有类名是哈希化的（如 `i7cW1UcwT6ThdhTakqFm`），选择器必须用 placeholder / text / accept 属性匹配

## 6. 待调研补全结果（2026-08-23 第二轮实测）

| 待调研项 | 实测结果 | 状态 |
|---|---|---|
| ① 封面"从正文选图" | **无此选项**——点「添加封面」仅触发原生文件选择框（OS 级），格式 JPEG/JPG/PNG | ✅ 已确认 |
| ② 投稿至问题搜索框 | 点「投稿至问题」→「我知道了」后 extract **未捕获搜索框**（隐藏 DOM）；2 次尝试无果 | ⚠️ 待人工确认 |
| ③ 创作声明选项列表 | 每次点击都弹说明弹窗（**无"已读标记"**）；「我知道了」后选项列表 extract 不可见；默认"无声明" | ⚠️ 待人工确认 |
| ④ 话题输入框 | 说明弹窗同规律；DOM 探针已知选择器 `input[placeholder*="搜索话题"]`（隐藏态）；**上限未知** | ⚠️ 待人工确认 |
| ⑤ 发布确认弹窗 | **未点击**（系统关键操作审批门拦截）；正式发布时需人工确认 | 🔒 发布时确认 |

### 关键新发现（能力边界）

1. **browser_local extract 只返回可见文本**——所有发布设置项的深层控件（搜索框/选项列表）是隐藏 DOM 或弹层，extract 无法捕获
2. **说明弹窗无"已读标记"**——每次点击设置项都先弹「我知道了」，不存在"记住跳过"
3. 深层选择交互（选问题/选话题/选声明）**超出 browser_local 能力边界** → 按分工原则归人工完成，或等 playwright 真实浏览器通道可用后补探针

### SOP 补充

- 自动化发布流程能覆盖：填标题 → 输正文 → 插图 → 自动存草稿 → 预览（人工确认）
- 人工兜底环节：封面选择、投稿至问题、创作声明、话题、最终发布确认

## 7. 草稿箱清理 SOP（2026-08-23 实测成功）

- **列表确认**：`text=草稿箱` → extract 确认篇数与标题
- **删除按钮**：`text=删除 >> nth=N`（N = 卡片序号-1，从 0 计）
- **确认弹窗**：点删除后 extract 确认出现"删除后无法恢复"
- **确认按钮（关键）**：**`button:has-text("确定")`** ✅ 可靠
  - ❌ `div:has-text("删除后无法恢复") >> text=确定` 不可靠（:has-text 匹配祖先容器，可能点到别处）
- **每删 1 篇后 extract 验证数量减 1**，再删下一篇（nth 会随列表收缩变化）
- 实测：5→4→3→2 全部成功，每次 `button:has-text("确定")` 一次命中
