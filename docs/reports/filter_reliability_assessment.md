# 过滤网可靠性评估报告

> 日期：2026-08-15
> 目的：「图书馆」体系最后质检——过滤网是选择层，决定给 Agent 什么数据。漏投喂→瞎猜，误投喂→误导，摘要失真→丢关键信息。
> 方法：真实任务回放测试（任务 → 过滤后上下文 → 能否还原关键信息），三维度量化。

---

## 一、评估结果总览

| 维度 | 指标 | 结果 | 评级 |
|---|---|---|---|
| 变量抽取准确率 | 路径/标识符命中 | 10/10 + 10/10 | ✅ 高 |
| 模块过滤召回率 | 应保留的模块 | 100% 召回 | ✅ 高 |
| 模块过滤准确率 | 保留的模块 | 100% 准确 | ✅ 高 |
| 三层摘要保真 | 目标/完成/失败 | 全保留 | ✅ 高 |

**结论**：过滤网核心链路（变量抽取 → 模块裁剪 → 摘要保真）在当前测试集下可靠性高，无漏投/误投/信息丢失。

---

## 二、维度详情

### 维度1：变量抽取准确率（10 个真实任务样本）

样本覆盖：完整路径（clawsjoy_dev/core/...）、纯文件名（audit.py）、下划线函数（_is_path_escape/_save_state）、驼峰（verify_completion_report）。

**结果：路径 10/10、标识符 10/10**——正则抽取对常见代码标识符形态鲁棒。

### 维度2：模块过滤召回率（20 模块，任务指向 2 个）

构造 20 个无关模块 + 2 个任务相关模块，任务描述指向 security.py + audit.py。

**结果：保留恰 2 个（security.py + audit.py），100% 召回 + 100% 准确**——无漏投、无误投、无膨胀。

### 维度3：三层滚动摘要保真

4 条消息（2 用户 + 2 assistant，含完成与失败）→ 语义摘要。

**结果：task_goal 保留任务描述、completed 保留完成步骤、failed_attempts 保留失败原因**——关键信息无丢失。

## 三、已知局限（诚实评估）

| 局限 | 影响 | 后续建议 |
|---|---|---|
| 变量抽取依赖正则 | 罕见命名（如无扩展名、中文文件名）可能漏 | 评估样本扩充到 50+，加入负样本 |
| world_model 实际只有 15 模块、3 个有骨架 | 真实模块未入库，过滤基准弱 | 补全 world_model 入库（真实 core/ 模块）|
| 依赖图不存在（dependency_graph.json）| 依赖链注入空转 | 生成依赖图（P2）|
| 摘要保真只测了 4 条消息 | 长任务（50+ 轮）摘要质量未验证 | 用真实长任务回放测试 |
| 未测「过滤后 Agent 能否答对原任务」端到端 | 最关键的质检未做 | LLM 回放：任务→过滤上下文→让 Agent 还原 |

## 四、风险评级

| 等级 | 项 | 依据 |
|---|---|---|
| 🟠 中 | world_model 覆盖不全 | 真实模块未入库（只有 3 个 _*.py 测试文件有骨架），过滤基准弱 |
| 🟡 低 | 正则抽取边界 | 10/10 通过但样本有限 |
| 🟡 低 | 摘要长任务保真 | 4 条消息验证通过，50+ 轮未测 |
| ✅ 无 | 过滤逻辑本身 | 召回/准确/保真全绿 |

---

## 五、结论与建议

**过滤网核心逻辑可靠**（三维度全绿），但**数据基础薄弱**：world_model 只覆盖测试文件、依赖图缺失——这不是过滤逻辑的问题，是**上游数据入库不完整**。

建议优先级：
1. **补全 world_model**：把真实 core/ 模块（security.py/audit.py/tool_router.py 等）入库（P1）——让过滤有完整基准
2. **LLM 端到端回放**：任务 → 过滤上下文 → Agent 还原关键信息（P1，最接近真实质检）
3. **依赖图生成**：dependency_graph.json 缺失（P2）
4. **评估样本扩充**：50+ 含负样本（P2）
