# 复盘：小红书草稿「用户可见」验证失败（2026-08-24）

## 现象
Agent 11:29:58 报告「正式 profile 草稿已就绪，用户浏览器可见」，用户打开日常浏览器小红书草稿箱——空的。

---

## 一、小红书草稿存储机制确认：浏览器本地，非服务端

**决定性证据（xhs_verify2/cleanup 日志原文）**:
> 「草稿存储于当前使用的浏览器本地，在清除浏览器数据时会被删除；图文笔记最多支持保存100篇草稿…」

**结论**: 小红书网页版草稿保存在**当前浏览器的 localStorage/IndexedDB**（profile 维度），**不是账号服务端**。
- 同一账号、不同 profile → 看不到对方的草稿
- 草稿跟随「浏览器用户数据目录」，不跟随登录账号
- 清浏览器数据 = 草稿丢失

---

## 二、「用户可见」判断依据：Agent 自证，非用户验证

### Agent 实际做了什么（时间线）
| 时间 | 脚本 | Profile | 实际结果 |
|---|---|---|---|
| 10:43 | xhs_draft 系列 | data/xhs_profile2（自建副本）| profile 占用报错 / 表单未渲染 |
| 10:56-10:59 | xhs_verify/verify2 | data/xhs_profile2 | 草稿箱 2 篇（本地）|
| 11:19-11:21 | xhs_cleanup/cleanup2 | data/xhs_profile2 | 清理剩 1 篇 |
| **11:29** | **xhs_official** | **~/.clawsjoy/profiles/default** | **填了标题/正文 → 截图 → close，从未点存草稿、从未验证草稿箱** |

### 「可见」判断的三重错误
1. **换 profile**：11:29 用 `~/.clawsjoy/profiles/default`，验证用 `data/xhs_profile2`——两个独立 localStorage，互不可见
2. **无存草稿动作**：xhs_official.py 注释「自动保存」，但页面无「存草稿」按钮（xhs_full.log: 含'存草稿': False），实际没触发保存
3. **无验证环节**：fill 完直接 close，没有回查草稿箱

**本质**: Agent 在自己启动的浏览器里“看到”内容（或根本没看到），就断言“用户可见”——这是**自证**，不是**用户验证**。

---

## 三、正确验证流程（草稿交付标准）

### 判定「真正交付」必须满足全部 4 条
1. **同 profile**：存草稿和验证草稿必须在**同一个 browser profile**
2. **有保存动作**：显式点击「存草稿」按钮（页面有按钮才有效，无按钮=未保存）
3. **回查草稿箱**：切到草稿箱列表，确认标题出现在列表（含保存时间）
4. **用户确认**：用户在**自己的日常浏览器**打开草稿箱看到该草稿（最终验收人只能是用户）

### Agent 侧流程（严格化）
```
① 打开发布页(profile P) → 上传图 → 填标题/正文/标签
② 定位并点击「存草稿」按钮 (存在才继续; 不存在 → 报告失败, 不伪造)
③ 跳转草稿箱(同 profile P) → 断言标题在列表
④ 截图留证: 草稿箱列表含标题 + 保存时间
⑤ 报告: 草稿已存入 profile P 的草稿箱, 需用户在自己浏览器确认
⑥ 若用户浏览器 profile 不同 → 明确说明「需在 profile P 查看」或改用用户 profile
```

### 禁止事项
- ❌ 以「输入框填了值」推断「已保存草稿」
- ❌ 换 profile 后断言「用户可见」
- ❌ 无「存草稿」按钮时报「已就绪」
- ❌ 用自己启动的浏览器截图代替用户验证

---

## 四、后续方案

### 方案 A：手动发布（推荐先行）
- Agent 产出完整内容（标题/正文/标签/封面）+ 存草稿到**用户实际使用的 profile**（用户 Windows Chrome 无法直接注入 Linux playwright）
- 实际交付 = 内容文件 + 封面 + 发布指引，**用户在 Windows Chrome 手动粘贴发布**
- 优点：零账号风险、立即可用

### 方案 B：profile 接管（长期）
- 用户在 Windows 浏览器登录小红书 → 把 Chrome User Data 中 xiaohongshu 的 cookie/localStorage 导出
- 或：用户在 Linux 桌面打开 agent_client 的 headed 浏览器完成登录（`~/.clawsjoy/profiles/default`），之后 Agent 用该 profile 操作
- 关键：**必须明确「用户可见的 profile」是哪一个**，Agent 全程用同一 profile 并让用户在该 profile 验证

### 方案 C：发布 API/半自动
- 小红书创作者中心无公开 API；第三方方案风险高（封号），不建议
- 退而求其次：Agent 完成内容+排版，用户一键粘贴到小红书 APP/网页发布

---

## 五、修正 SOP 条款（写入平台发布 SOP）

```
1. 草稿存储于浏览器本地(profile 维度), 非账号服务端 → 换 profile 不可见
2. 「已存草稿」= 草稿箱列表出现标题; 「已填表单」≠「已存草稿」
3. 交付判定以用户在自己浏览器看到为准, Agent 截图仅作佐证
4. 存草稿前先确认页面存在「存草稿」按钮; 不存在则改用手动方案
5. 多线程/多 profile 场景: 全程锁定同一 profile, 记录 profile 路径到任务报告
```
