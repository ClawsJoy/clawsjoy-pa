# 执行层：PA 的核心特性

> 2026-10-30 · 产品原则 ｜ 语义分析 → 用户授权 → 环境感知 → 拆解 → 追踪 → 审核 → 汇总呈报

## 一、一句话

**GPT 给答案；PA 给“经用户授权、基于本机环境、可追踪、可审核、可汇报”的执行。**

## 二、三平面

~~~text
数据/上下文平面
  本地文件、笔记、台账、浏览器、设备、事件、画像
        ↓ 提供事实与环境
执行/治理平面
  语义分析 → 授权 → 环境感知 → 拆解 → 追踪 → 审核 → 呈报
        ↓ 产出结果与证据
表达/交互平面
  自然对话、流式、卡片、摘要、报告
~~~

数据面保证“知道什么”，执行面保证“做了什么”，表达面保证“用户看懂”。

## 三、执行七段

### 1. 语义分析

- 用户要什么；
- 对象、范围、约束、时限；
- 风险等级：只读/写入/外发/支付/删除；
- 是否需要澄清。

输出：任务意图 + 约束 + 风险 + 不确定项。

### 2. 用户授权

执行前必须让用户看到：

- 要做什么；
- 为什么；
- 用哪些能力/插件；
- 读写哪些数据；
- 是否出机；
- 预计耗时/成本；
- 如何停止。

授权粒度：

- 本次；
- 本任务；
- 本会话；
- 长期（高风险慎用）。

### 3. 环境感知

- 本机文件/应用/浏览器/设备状态；
- 工作区结构；
- 相关上下文/历史；
- 可用能力与限制。

原则：**先感知再行动；感知结果带来源；不假设。**

### 4. 拆解

- 目标拆成步骤/DAG；
- 每步：输入、输出、能力、验收；
- 可并行/串行；
- 失败回退；
- 预算与停止条件。

### 5. 执行与追踪

- 每步状态：待办/进行/完成/失败/跳过；
- 事件流、产物、回执；
- 可暂停、恢复、停止；
- 不静默重试、不静默改范围。

### 6. 审核

- 独立于执行者；
- 检查产物是否真的存在；
- 命令/写入/发布是否有回执；
- 结论是否有出处；
- 未核实项必须列出。

### 7. 汇总与呈报

用户面只给：

- 结果；
- 关键证据；
- 改了什么；
- 未完成/待核实；
- 下一步建议。

内部判据、面册、源码片段进“详情”，不占主屏。

## 四、PA 的护城河

不是“模型更聪明”，而是：

- **能办事**：本地数据 + 工具 + Agent；
- **可授权**：做事前用户点头；
- **可追踪**：每步有状态；
- **可审核**：不是模型自说自话；
- **可汇报**：结果和证据分开；
- **可停止**：随时刹车；
- **可回退**：原件/版本/归档。

## 五、和聊天机器人的区别

| 维度 | 聊天机器人 | PA |
|---|---|---|
| 主要输出 | 文本 | 结果 + 证据 + 变更 |
| 权限 | 无 | 逐项授权 |
| 环境 | 不知道本机 | 本机感知 |
| 执行 | 不落地 | 真执行 |
| 追踪 | 无 | 步骤/事件/回执 |
| 审核 | 模型自评 | 独立核验 |
| 失败 | 编一个答案 | 如实报告 |
| 停止 | 关对话 | 暂停/停止/回退 |

## 六、当前 PA 的缺口

- 授权卡不统一，常在执行中才弹；
- 环境感知有，但没形成统一“任务上下文”；
- 拆解/追踪散在 Agent/台账/事件里；
- 审核多为事后；
- 呈报仍会露出内部判据；
- 用户看不到“现在做到哪一步”。

## 七、下一步

1. 统一任务对象：意图/约束/风险/授权/步骤/产物/回执；
2. 执行前一张授权卡：范围/权限/数据/停止；
3. 任务控制台：步骤、状态、暂停、恢复、停止；
4. 独立审核：产物存在性 + 出处 + 未核实；
5. 呈报模板：结果/证据/变更/待办；
6. 全链路事件与回执可查。

## 八、验收

- 用户知道 PA 要做什么、凭什么做、动哪些数据；
- 执行中能看到步骤和进度；
- 失败不编，未核实明说；
- 结果有证据，详情可展开；
- 关掉模型，执行与审核仍成立。

（完）
