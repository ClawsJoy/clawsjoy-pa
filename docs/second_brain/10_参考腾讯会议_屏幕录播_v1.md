# 参考腾讯会议：屏幕录播 UX 与技术现实（v1）

> 2026-10-29 · 第一大脑文档 ｜ 学交互，不复制会议基础设施

## 0 一句话

**学腾讯会议的“一键、清楚、可恢复、会后有结果”；不学它的 SFU/云端会议/账号体系。**

## 1 值得学的 UX

### 会前

- 一键开始，不让你先配一堆参数；
- 选源清楚：窗口/屏幕/区域，显示缩略图与名字；
- 麦克风电平、摄像头预览；
- 明确提示：会录到什么、存哪、多久删；
- 权限被拒时给人话＋去处，不白屏。

### 会中

- 悬浮小控制条：计时、暂停、静音、停止；
- 录制指示明显，不可偷偷录；
- 暂停/恢复不中断文件；
- 窗口可最小化，不挡内容；
- 断网/磁盘满/权限变化有明确提示。

### 会后

- 停止即处理，显示进度；
- 自动生成：转写、摘要、章节、待办；
- 可回看时间线、点章节跳转；
- 可分享/导出/删除；
- 失败可恢复，不丢文件。

## 2 技术现实：腾讯会议 vs PA

| 维度 | 腾讯会议类 | PA 屏幕录播 |
|---|---|---|
| 场景 | 多人实时会议 | 单人本地录屏 |
| 媒体 | SFU/云端混流/低延迟 | 本地单路采集 |
| 音频 | 3A、回声消除、系统音频 | 先麦克风，系统音频后置 |
| 编码 | 硬件/自适应码率 | 本地 webm/VP9 或 H.264 |
| 存储 | 云录制/本地录制 | 只本地 |
| 账号 | 会议号/登录 | 本地，无账号 |
| 结果 | 会议纪要/字幕 | 时间线 note＋步骤/待办 |

结论：**不要为了录屏去造 SFU；本地单路采集简单得多。**

## 3 技术约束（Windows/Electron）

- Electron desktopCapturer 选源；getUserMedia＋chromeMediaSource:desktop；
- 窗口/屏幕/多显示器/DPI 要处理；
- DRM/受保护窗口可能黑屏，要明说；
- 系统音频（Windows 回环）首版不做；先麦克风；
- MediaRecorder 出 webm；长录要分片/恢复；
- 硬件编码因机器而异；CPU 兜底；
- 磁盘满、权限撤销、录到 PA 自己，都要防；
- 权限：display-capture 单独放行，不能沿用 microphone 的白名单。

## 4 PA 的屏幕录播 P0

~~~text
点「录屏」
 → 选窗口（默认）/屏幕
 → 3 秒倒计时
 → 录画面＋麦克风
 → 悬浮控制条：计时/暂停/停止
 → 停止 → 本地转写＋关键帧
 → 生成「录屏笔记」
~~~

录屏笔记：

- 摘要；
- 时间线 mm:ss；
- 转写全文；
- 关键截图；
- 步骤/待办；
- 原视频本地引用。

## 5 会前/会中/会后清单

### 会前

- 源选择＋缩略图；
- 麦克风电平；
- 预计占用空间；
- 保留期；
- 隐私提示。

### 会中

- 计时；
- 暂停/恢复；
- 静音；
- 停止；
- 录制指示；
- 异常提示。

### 会后

- 处理进度；
- 转写；
- 关键帧；
- note；
- 可问答/可删除/可导出。

## 6 失败模式

- 磁盘满；
- 权限被拒；
- 受保护窗口黑屏；
- 录制中窗口关闭；
- 麦克风被占用；
- 编码器崩溃；
- 长录文件损坏。

每个都要给人话＋去处，不假装成功。

## 7 指标

- 选源到开录 < 3 秒；
- 停止到出 note < 1 分钟（10 分钟录屏）；
- 录制失败率 < 2%；
- 10 分钟文件大小可预期；
- 转写可读率；
- 用户会回看/搜索。

## 8 不学/不做

- 不做会议号/登录/多人；
- 不做 SFU/云端混流；
- 不做云录制；
- 不做虚拟背景；
- 不做长录默认；
- 不把视频上链。

## 9 PA 的差异

腾讯会议记录“会议”；
PA 记录“工作”，并把它变成可搜索、可执行、可引用的第二大脑。
