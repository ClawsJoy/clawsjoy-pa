# 第二大脑 · 笔记本（对标 Google NotebookLM / Gemini Notebook）

> 2026-10-31 · P1 实装记录。目标：把「记事本」升级为成熟笔记本产品，而不是文件列表。
> 本地优先：来源文件在本机、索引可重建、模型不可用时照实回落，不假装。

## 1. NotebookLM 的产品骨架（我们对照的六件事）

1. 多笔记本：每个笔记本是一组来源 + 对话 + Studio 产出；
2. 来源：PDF／网页／文本／音视频等，来源列表可管理；
3. 限定问答：只基于本笔记本来源回答，答案带可点的行内引用；
4. Notes：对话/产出可存为笔记；
5. Studio：摘要、常见问题、学习指南、思维导图、音频/视频概览等；
6. 共享与协作（我们暂不做，本地优先）。

## 4. 接口（本机回环）

- GET/POST /v9/pa/notebooks
- GET/PATCH/DELETE /v9/pa/notebooks/<id>
- GET /v9/pa/notebooks/<id>/sources
- POST /v9/pa/notebooks/<id>/sources/text | url | pdf
- POST /v9/pa/notebooks/<id>/ask
- POST /v9/pa/notebooks/<id>/studio（summary/faq/study/mindmap）
- POST /v9/pa/notebooks/<id>/notes（存产出）
- 来源仍走 /v9/pa/notes*（同一 note 模型）

## 5. 数据落点

    %LOCALAPPDATA%/ClawsJoyPA/data/workspace/
      notebooks.json          # 笔记本元数据（原子写）
      notes/<id>.md           # 来源/笔记正文（文件是真相）
      index.sqlite            # FTS5＋notebook_id 索引（可重建）
      sources/<notebook>/     # PDF 原文件

## 6. 验收口径

- 建笔记本 → 加来源 → 问一句 → 答案只引本笔记本 → 点 [n] 打开原文 → Studio 生成 → 存为笔记；
- 模型不可用 ⇒ 明确显示摘录与原因；
- 删笔记本 ⇒ 来源退回未归档，不删用户笔记；
- 重启后笔记本、来源、对话仍在。
