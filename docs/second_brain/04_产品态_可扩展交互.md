# 产品态：为未来交互留骨架（v1）

> 2026-10-29 · 第一大脑文档 ｜ 目标：文本/语音/PDF/摄像头/穿戴都接得上，不重写产品

## 0 一句话

**PA 的稳定产品态 ＝ 采集无关的工作区 ＋ 结构化记忆 ＋ 有门禁的行动 ＋ 可追溯回执。**

不是“聊天框”，也不是“笔记软件”，而是这四件事的组合。

## 1 五个稳定契约

### ① Capture（采集）

任何输入都变成同一种信封：

~~~text
source_type: text | voice | pdf | html | md | image | video | sensor
device_id, started_at, ended_at
consent, retention, sensitivity
asset_hash, raw_asset_ref
~~~

- 摄像头/麦克风只是新的 source_type；
- 不把“消息”当唯一输入；
- 原始资产内容寻址保存。

### ② Artifact（工件）

任何可编辑产物：

~~~text
note | transcript | clip | table | canvas | report | task
provenance: capture_id(s)
links, tags, created/updated
~~~

- Note 是默认工件，但不是唯一；
- 视频片段/表格/画布同一套引用；
- 用户可编辑，Agent 可解析。

### ③ Memory（第一大脑）

从工件抽取：

~~~text
observation | fact | entity | relation | task | decision
citations: artifact_id + anchor (page/time)
confidence, at
~~~

- 不存原始视频；
- 只存理解与出处；
- 可重建。

### ④ Action（行动）

~~~text
tool, risk, scope, approval, receipt, undo?
~~~

- 所有动手都走门禁；
- 有回执；
- 可停止。

### ⑤ Renderer（呈现）

- workspace：note/表格/画布/时间线/播放器；
- inbox：未整理采集；
- ask：带出处回答；
- 同一数据，多种视图；
- 不把 UI 绑死在“聊天气泡”。

## 2 加一个摄像头，只改三处

1. 新增 Capture adapter（摄像头/麦克风/屏幕）；
2. 新增 Artifact renderer（片段/时间线/关键帧）；
3. 新增权限/同意 UI。

**不改**：Memory schema、Action 门禁、workspace 基本结构、Note 模型。

## 3 产品界面骨架

- **Today**：今天发生了什么、待整理、待办、问一句；
- **Inbox**：所有采集（文本/录音/文件/摄像头）待整理；
- **Workspace**：笔记/表格/画布/片段；
- **Brain**：搜索/问答/出处；
- **Doors**：权限/门禁/回执；
- **Summon**：随时记/问/做。

文本是主交互，但不是唯一入口。

## 4 路线

- H1（现在）：文本＋语音＋PDF/MD＋note＋带出处问答；
- H2：手机摄像头显式采集＋短片/截图；
- H3：穿戴/环境记忆 opt-in＋多传感器；
- 每一层都复用同一 Capture/Artifact/Memory/Action。

## 5 现在就要留的接口

- capture 表带 source_type/device/consent，即使先只用 text；
- artifact 表带 provenance/anchor，即使先只有 note；
- memory 表带 citation/anchor，即使先只有文本；
- 权限模型能表达 camera/mic/screen；
- UI 有 Inbox 概念，不只 Today 卡片。

## 6 不要做

- 不为摄像头提前造硬件；
- 不把视频塞进第一大脑；
- 不默认常开/上云；
- 不把产品做成“聊天框＋插件”；
- 不过度抽象到无法交付。

## 7 验收标准

- 给一条假 sensor 事件，能落成 artifact＋memory＋引用，不改 schema；
- 给一段录音，能落成 transcript note；
- 给一个 PDF，能带页码引用；
- 未来接摄像头时，只加适配器与渲染器。
