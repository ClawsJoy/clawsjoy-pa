# 双大脑概念：第一大脑 / 第二大脑（v1 校正）

> 2026-10-29 · 第一大脑：Agent 可读的结构化记忆核心 ｜ 第二大脑：用户＋Agent 可交互的多格式工作区

## 0 一句话

- **第一大脑**：Agent 自己看得懂、可检索、可推理的结构化记忆；用户可查但不以此为主要界面。
- **第二大脑**：用户看得见、摸得着、可编辑的多格式工作区；Agent 通过工具读写它。

两者不是同一个东西；第二大脑的变更会被索引进第一大脑，第一大脑的结论会引用第二大脑的原文。

## 1 第一大脑（Agent-readable）

### 内容

- 事实／偏好／决策／任务／实体／关系；
- 事件时间线、出处（citation）、置信度；
- 语义索引、向量、关键词索引；
- 会话摘要、待办、未决问题；
- 工具结果与回执的结构化记录。

### 形态

- SQLite / JSONL / 向量库；
- 稳定 ID、schema、版本；
- **不是**一篇篇散文；散文属于第二大脑。

### 落点

~~~text
%LOCALAPPDATA%/ClawsJoyPA/first_brain/
  memory.sqlite
  events.jsonl
  embeddings/
~~~

### 规则

- Agent 可自动写入；
- 每条事实带出处与时间；
- 可重建索引；
- 用户可导出/删除；
- 默认不出机。

## 2 第二大脑（User + Agent workspace）

### 内容

- Markdown 笔记；
- 表格／看板；
- 画布／白板；
- 图表／时间线；
- PDF／图片／附件；
- 任务卡／报告／产出。

### 形态

- 文件系统 + 可视化 UI；
- 用户直接编辑；
- Agent 通过解析/工具读写；
- 多种格式，统一索引。

### 落点

~~~text
%LOCALAPPDATA%/ClawsJoyPA/workspace/
  notes/
  boards/
  canvases/
  tables/
  attachments/
  exports/
~~~

### 规则

- 用户是主编辑者；
- Agent 写入须人批（默认）；
- 改写前 snapshot；
- 可导出为 md/zip/PDF；
- Obsidian 可作为导入/导出格式，不是依赖。

## 3 两者关系

~~~text
用户编辑第二大脑（笔记/表格/画布）
        ↓ 索引/解析
第一大脑（事实/实体/关系/出处）
        ↓ 检索/推理
Agent 回答、提案、执行
        ↓ 人批
写回第二大脑（带快照/回执）
~~~

- 第二大脑是**证据与工件**；
- 第一大脑是**理解与记忆**；
- 不要把所有原文塞进第一大脑；
- 不要把第一大脑的结构强加给用户当界面。

## 4 产品含义

- 用户为**第二大脑**留下来：看得见、能编辑、能带走；
- 用户为**第一大脑**信任 PA：它真的记得、有出处、越用越懂；
- 只有第二大脑 ⇒ 只是笔记软件；
- 只有第一大脑 ⇒ 只是黑箱聊天；
- 两者合起来才是 PA。

## 5 P0

1. 第二大脑：note 编辑/搜索/多格式（先 md＋表格＋附件）；
2. 第一大脑：索引/事实/出处/任务；
3. 问答：检索第二大脑 → 第一大脑组织 → 带出处回答；
4. 写回：提案 → 人批 → 写第二大脑 → 快照；
5. Obsidian 导入/导出（可选）。

## 6 命名说明

- \`docs/second_brain/\` 是**第一大脑的决策文档**（历史路径名，暂不改）；
- PA 运行时的第一大脑在 \`first_brain/\`；
- 第二大脑在 \`workspace/\`；
- 不要把三者混为一个目录。
