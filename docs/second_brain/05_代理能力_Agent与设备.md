# 代理能力：Agent 与设备（v1）

> 2026-10-29 · 第一大脑文档 ｜ PA 不只是聊天入口，还是 Agent 调度层＋设备代理层

## 0 一句话

**PA 向上统管各厂 Agent，向下代理家里设备，中间用本地门禁/回执保证可信。**

## 1 两类代理

### ① Agent 代理（管 AI）

- 大厂模型/Agent：OpenAI、Claude、Gemini、DeepSeek、Kimi、通义等；
- 本地模型/Agent：Ollama、本地执行器；
- 专业 Agent：浏览器、编码、文档、图像、工作流；
- 接入方式：API、MCP、CLI、浏览器自动化；
- PA 负责：凭据、能力卡、路由、预算、健康、降级、回执。

用户不需要记“哪家能干什么”；PA 按任务选、按权限放行。

### ② 设备代理（管家）

- 摄像头：RTSP/ONVIF/厂商云；
- 智能家居：Matter/Thread、Home Assistant、Zigbee/WiFi；
- 传感器：温湿度、门窗、人体；
- 执行器：灯、插座、空调、门锁、窗帘；
- 机器人/音箱/电视等。

PA 负责：发现、状态、控制、场景、告警、回执。

## 2 三层结构

~~~text
能力注册表（Registry）
  ├─ Agent：能力/凭据/成本/健康
  └─ Device：类型/位置/协议/状态
        ↓
策略与门禁（Doors）
  ├─ 谁能用、能做什么、何时、多久
  └─ 高风险须人批
        ↓
适配器（Adapters）
  ├─ MCP / API / CLI / 浏览器
  └─ Matter / Home Assistant / ONVIF / RTSP
~~~

## 3 一次请求怎么走

~~~text
用户：“看看客厅现在有人吗”
  → PA 识别意图：摄像头/客厅/快照
  → 查注册表：客厅摄像头在线
  → 门禁：摄像头读取权限、是否在家
  → 适配器：抓一帧
  → 第一大脑：事件/观察
  → 回执：时间、设备、置信度
~~~

不是“直接调某个品牌 App”。

## 4 例子

- “让 Claude 写方案，DeepSeek 查资料，本地模型总结” → PA 分派、汇总、回执；
- “看看门口” → 摄像头快照/短录；
- “把客厅灯打开” → 智能家居控制（低风险）；
- “门锁打开” → 高风险，必须人批＋二次确认；
- “今天家里有人来过吗” → 摄像头事件＋时间线；
- “空调调到 26 度” → 设备控制＋状态回执。

## 5 权限与安全

- 每个 Agent/设备单独授权；
- 物理动作分级：读状态 < 开灯 < 门锁/燃气/加热；
- 高风险必须人批、限时、可撤销；
- 凭据进本地 vault，不进日志；
- 摄像头/麦克风有指示灯与保留期；
- 设备走本地优先，云端可选；
- 全量审计：谁、何时、对哪个设备、做了什么；
- 失败安全：断网/超时默认不执行。

## 6 数据落点

- 设备事件/观察 → 第一大脑（事实/实体/时间线）；
- 截图/片段/笔记 → 第二大脑 workspace；
- 原始视频默认本地加密，不上云；
- 保留期可配，可一键删。

## 7 MVP

1. Agent 注册表：把现有“席”升级为能力卡＋凭据＋回执；
2. 手机摄像头/RTSP 快照 → note；
3. Home Assistant 只读状态（灯/温度/传感器）；
4. 低风险控制＋人批；
5. 每设备/每 Agent 权限页；
6. 事件时间线。

不做全品牌适配；先 MCP/Home Assistant/ONVIF 三条。

## 8 非目标

- 不替代 Home Assistant；
- 不做全屋厂商云；
- 不默认云端视频；
- 不无审批开门锁/燃气；
- 不做“全自动自治家庭”；
- 不把设备数据上链。
