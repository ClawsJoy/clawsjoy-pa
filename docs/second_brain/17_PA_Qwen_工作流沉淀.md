# PA + Qwen：表达像 GPT，工作流靠 PA 沉淀

> 2026-10-30 · 产品原则 ｜ 我们不提供 GPT；GPT 只是体验基准

## 一、先纠正一句话

不要说“PA 提供 GPT”。

真实是：

~~~text
PA（约束/数据/执行/记忆/工作流）
  + 本地 qwen（表达/推理/摘要）
  = 用户感到“像 GPT 一样会沟通”
~~~

GPT 是**体验基准**，不是依赖。PA 可以完全不接 OpenAI。

## 二、分工

| 层 | 谁负责 | 说明 |
|---|---|---|
| 自然表达 | qwen | 接话、解释、追问、摘要 |
| 事实与出处 | PA 数据层 | 本地文件、笔记、台账、证据 |
| 权限与边界 | PA 治理层 | 授权、审批、沙箱、停止 |
| 执行与追踪 | PA 执行层 | 拆解、工具、Agent、回执 |
| 工作流沉淀 | PA 记忆层 | 成功路径 → 可复用 skill/playbook |
| 模型不可用 | PA 降级 | 显示事实卡，不编 |

qwen 不拥有事实，PA 不假装会说话。

## 三、工作流沉淀闭环

~~~text
任务
 → 语义分析
 → 用户授权
 → 环境感知
 → 拆解
 → 执行
 → 追踪
 → 审核
 → 呈报
      ↓
 工作流记录
（步骤/工具/权限/验收/失败/耗时）
      ↓
 候选 skill / playbook
      ↓
 用户确认（或显式“记住这个流程”）
      ↓
 下次复用 / 适配 / 失效
~~~

## 四、沉淀什么

一条可复用工作流应包含：

- 触发条件：什么任务适用；
- 输入：需要哪些文件/信息；
- 步骤：顺序/并行；
- 工具/插件：用了什么；
- 权限：读了什么、写了什么；
- 审核：怎么判断成功；
- 失败模式：常见错误与回退；
- 产物：输出什么；
- 版本：工具/模型变化后是否失效。

只存“步骤文本”不够，必须带**权限、验收、失败**。

## 五、两种沉淀方式

### 显式

用户说：

- 记住这个流程；
- 设为模板；
- 以后都这样做。

PA 生成 skill 草稿，用户确认后入库。

### 隐式

PA 发现同类任务多次成功：

- 生成候选工作流；
- 标注“从 N 次执行归纳”；
- **必须用户确认**才启用；
- 不自动改默认行为。

## 六、边界

- 工作流不携带超出原任务的权限；
- 插件/工具变更 ⇒ 工作流标“待复验”；
- 失败路径也沉淀，避免重复踩坑；
- 用户可查看、编辑、删除、导出；
- 模型不可用 ⇒ 工作流仍可手动执行。

## 七、PA 现状

已有：

- 第二大脑、事件、台账、回执；
- Agent 分派、浏览器、录屏、语音；
- 本地 qwen；
- 证据链。

还缺：

- 统一工作流对象；
- 成功路径自动候选；
- skill 库与版本失效；
- 复用时的权限复核；
- 用户面“记住这个流程”入口。

## 八、下一步

1. 定义 workflow 记录 schema；
2. 执行结束生成“可复用候选”；
3. 用户确认入库；
4. skill 库：查看/编辑/删除/导出；
5. 复用前权限复核；
6. 工具变更触发失效标记；
7. qwen 只负责解释与适配，不负责改事实。

## 九、一句话

**GPT 给表达，qwen 给本地表达，PA 给约束、数据、执行和可复用工作流；用户越用，PA 越懂他的做法，而不是越会编。**
