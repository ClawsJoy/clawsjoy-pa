# 交互与多模态采集：文本为主，note 为核（v1）

> 2026-10-29 · 第一大脑文档 ｜ 第二大脑：PA workspace

## 0 一句话

**用户与 PA 的主交互是文本；语音/视频/PDF/HTML/MD 是采集入口，统一落成带出处的 note；note 是第二大脑的原子工件。**

## 1 为什么 note 是核心

- 文本可编辑、可检索、可引用、可迁移；
- 语音转写、PDF 解析、网页剪藏，最终都要变成可改的文本；
- Agent 读写 note 比读写视频/音频可靠；
- 用户看得见、改得动，才有信任。

## 2 采集适配器

| 输入 | 采集 | 解析 | 锚点 | 优先级 |
|---|---|---|---|---|
| 文本 | 输入框/热键 | 直接 | note id | P0 |
| 语音 | 录音/上传 | 本地 ASR | 时间戳 | P0 |
| PDF | 拖入/选文件 | 文本＋版面；扫描件 OCR | 页码 | P0 |
| HTML | 剪藏/URL | reader 模式；去广告 | URL＋抓取时间 | P1 |
| MD | 导入/新建 | 原生 | 文件路径 | P0 |
| 图片 | 拖入 | OCR/描述 | 图片 id | P1 |
| 视频 | 拖入/录制 | 音轨转写＋关键帧 | 时间码 | P2 |

原则：

- 原文件进 workspace/attachments，不丢；
- 解析结果进 note，保留出处；
- 解析失败 ⇒ 明说失败，不假装有内容；
- 默认本地处理，云端可选。

## 3 统一流水线

~~~text
采集（文本/录音/PDF/HTML/MD/图片/视频）
  → 原始资产（attachments）
  → 转写/抽取（transcript/extract）
  → Note（可编辑，带 provenance）
  → 第一大脑索引（事实/实体/任务/出处）
  → 问答/行动/回执
~~~

## 4 Note 形态

- 普通笔记；
- 转录稿（带时间戳、说话人）；
- 文档摘录（页码锚点）；
- 网页剪藏（URL＋时间）；
- 日报/周报；
- 任务清单；
- 附件卡片。

## 5 记事本 UI

- 全局热键：记一笔 / 开始录音；
- Today：快速记、最近笔记、待整理 inbox；
- 左侧「脑」：全部笔记/搜索/标签/反链；
- 笔记页：编辑｜预览｜出处｜附件｜相关；
- Inbox：未整理的采集，一键转 note/任务；
- 录音页：转写、分段、说话人、摘要、待办。

## 6 整天录音（重点场景）

很多 GPT 用户把一天工作录音喂给模型。PA 可以做，但必须：

- **显式开始/停止**，状态可见，不默认常开；
- 本地 ASR 优先；云端需明示出机；
- 分片/静音切分，避免一个 8 小时巨文件；
- 保留原音频，转写稿可编辑；
- 自动生成：时间线、摘要、待办、决策、引用；
- 存储/电量/隐私提示；
- 合规：录音同意、保留期、删除、加密。

价值：

> 用户不用“写日记”，说一天，PA 把它变成可搜索的第二大脑。

## 7 不同格式的边界

- 视频首版只做音轨＋关键帧，不做完整视频理解；
- PDF 扫描件 OCR 失败要明示；
- HTML 只存可读正文＋快照，不执行脚本；
- 音频默认不上传；
- 所有解析结果可追溯原文。

## 8 P0 顺序

1. 文本 note＋快速记；
2. 语音录音→本地转写→note；
3. PDF/MD 导入＋页码/文件锚点；
4. 搜索＋带出处问答；
5. Inbox 整理＋任务提取；
6. HTML 剪藏；
7. 图片/视频后置。

## 9 与第一大脑

- note 是证据，第一大脑抽事实/任务/关系；
- 每个事实带 note id／时间戳／页码；
- 用户编辑 note ⇒ 重新索引；
- Agent 写 note 须人批＋快照。

## 10 非目标

- 不做完整视频编辑器；
- 不做常开监听；
- 不默认云转写；
- 不把音视频明文上链；
- 不先做多人协作。
