# PA 全新定义 v2（2026-10-30）

> 一句话：**PA 是老板的数字幕僚长，不是聊天框。**

## 1. 用户是谁

- 一个老板/一人公司负责人。
- 他要的是“事办成”，不是“模型回话”。
- 他没有时间盯五个席、读日志、配 key、查路由。

## 2. PA 是什么

PA = **产品壳** + **DSH 运行时** + **本地模型** + **权限/审批** + **记忆/证据/编排**。

- 产品壳：入口、界面、任务卡、状态、回执。
- DSH 运行时：计划、工具、观察、修正、恢复。
- 本地模型：默认离线可用；云模型是按需选项。
- 权限/审批：不可逆动作才停手。
- 记忆/证据/编排：记得住、说得清、派得动。

## 3. PA 不是什么

- 不是聊天机器人。
- 不是工程控制台。
- 不是“外部助手转发器”。
- 不是“已发·等回”的乐观界面。
- 不是多写者并行系统。

## 4. 用户只关心五件事

1. 我交办的事，做了没有？
2. 做到哪一步了？
3. 我不想让它做时，能不能立刻停？
4. 它说做了，凭什么？
5. 出错了，我能不能恢复？

## 5. PA+DSH 大于 1 的六个来源

| PA 提供 | DSH 单独没有 |
|---|---|
| 记忆：项目/决策/偏好 | 会话结束就忘 |
| 控制：停/排队/审批分级 | 强但不敢放权 |
| 责任：回执/证据/谁批 | 可能“说做了” |
| 连续：关窗/重启继续 | 会话断就断 |
| 本地：数据不出机 | 云端依赖 |
| 编排：PM/PD/CW 席位 | 单个 agent |

**若 PA 只转发 DSH，则 PA+DSH=1；若 PA 增加摩擦，则 <1。**

## 6. 用户路径验收

1. 打开即用，不配 key 也能本地聊。
2. 点发送，后端必须受理；未受理不许写“已发”。
3. 任何等待/执行态都能停；停后 active 立即清。
4. 任务可问进度、可插话、可排队。
5. 完成有回执：做了什么/动了哪些件/凭什么/能不能退。
6. 关窗再开，任务还在。
7. 不可逆动作才停手。

## 7. 当前差距

- 默认本地聊天仍有 Ollama tool 400。
- `/v9/cancel` 已同步 turn_registry，但还未做真实 active 端到端。
- 旧窗口直达 sendAgent 已改，但未做 UI 自动化验收。
- DSH HarnessPort 已有，但未接进 PA 聊天主路径。
- 对话与执行仍绑在单线程 busy。

## 8. 不做的事

- 不再用 CI 绿冒充产品可用。
- 不再用路由存在冒充功能可用。
- 不再先加功能再补基本功。
- 不再让用户看工程日志。
