## 编辑纪律（两个方向都适用）

1. **禁止整文件 cp**（批162 纪律）：dev↔live 只做**定点编辑**；确需搬运时**逐函数人工对账**并留痕。
2. 改 **dev** 前先 `diff` 本目录文件与 live 的同名文件：**不一致就先停**，走下面「分叉处置」。
3. 改 **live**（当前真源）时：`ast.parse` 先验 → 落盘 → **回读确认** → **dry-start** → 重启 → health 200。
4. **重启前必须 dry-start**（体检 105）；**提交门 = 完整回归集**（体检 46）。
5. **不许在本目录留下「只有 live 有」的改动而不记录**：live-only 改动要写进台账行 + 报告。

## 分叉处置（发现 dev≠live 时）

1. **先分级，别先动手**（体检 §十四 A1–A4）：剥 docstring 比 AST → 顶层语句语义归一 → diff 按「格式／语义等价／逻辑」分组计数；
2. **只报「逻辑差异行数」**才算风险；
3. 引号风格（`'` vs `"`）与换行/import 顺序**都属格式类**，但 **token 级判据对引号敏感** ⇒ 必须用**引号无关的 AST 归一**复核，否则会出假警报（批173 实测：逐行子串与 token 多重集两套判据**都出现引号导致的假阳性**）；
4. 对**每个逻辑不同的函数**逐条决定（取 live 版／合并），清单化留痕，**再**做 sha 对齐；
5. **不许「猜着对齐」** —— 判据不足就停下报告（体检 54/113）。
